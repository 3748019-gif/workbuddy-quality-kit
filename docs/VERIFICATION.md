## 这次修正的原因与方法

最终说明容易把全集与子集混淆、把未知概括为没有，或在另一处重复表述时漂移。技能将容易混淆的量分别命名并保留来源、范围与单位，再从实际成品找反例、检查跨处一致性。发现问题须修改实际文件和受影响说明，修正后回读。

新增 facts 从真实保存文件取得字段状态和行数，区分缺失、null、空字符串、空白、false与数值零。多行JSON正文最多12KiB，单行最多1000字节；超限明确失败，不截断后报成功。它不接收期望答案、不判断自然语言是否正确，也不证明数据来源选对。SHA前后核对用于识别保存版本，不是并发原子快照。

复核任务使用review_request.py handoff从同一记录派生完整文件清单和SHA，底层content_check.py handoff只承担文件身份检查，不可手填另一套清单绕过复核记录。回执对真实文件核对存在、版本和受支持格式的有限语法检查；单份文件最多20MiB，不直接接收任意摘要参数，也不宣称语义通过。大型或不支持格式的成果应保留并使用已有适用工具核验，不能仅因回执工具范围有限丢弃成果或将任务判失败。用户要求的分析须留在对应受核交付中，实际阻断仍须明确说明；明确聊天必答纳入回复，不能以链接替代。回执层减少检查结束后再次新增未经核对内容的机会，不单独解决报告理解和范围判断。

可选项目交付检查在明确的工作区内，按真实会话和回合登记 handoff 回执，并在结束响应时比较回复及文件版本；若不一致，最多自动反馈一次，纠正后重新核对。普通聊天、明确要求聊天分析、未登记回执或用户退出时不强制纯链接回复。回执一致只证明回复与保存版本匹配，不证明内容语义正确。宿主界面可能保留纠正前文字，失败提示也不保证可见；再次失败记录partial并停止自动续跑。项目Hook需单独兼容验证，普通技能安装成功不等于这个功能已启用。

本轮项目Hook实际验收平台：macOS。基础技能安装自检与项目Hook兼容性分别记录；旧安装器测试不能证明新增项目设置合并已安全，未测试平台不能据此宣称同等效果。

复杂材料与多条件任务的完整交付复核
先按原始要求声明全部必交文件路径。普通文件任务默认使用工具生成的中性文件回执；仅当用户明确要求聊天分析、必答结论或必须直接说明阻断时，才保存完整拟回复并在compare纳入--reply-file。不能为通过回执检查删掉必答内容，也不默认另写纠错长评。
来源阶段用review_request.py prepare固定要求、原始权威来源和必交清单，返回的agent_args原样交给真实原生Agent，mode=default沿用产品正常权限，任务仍限定只读。source不能用作者自产摘要、过程文件或待审旧稿；第一阶段可见声明路径以查漏，但不打开成品内容，不给作者推导或自评分：
PY SCRIPT/review_request.py prepare --root ROOT --work-root WORK --record WORK/review.json --task inputs/task.txt --source inputs/source.txt --model MODEL --required-artifact OUTPUT/report.md --required-artifact OUTPUT/result.json
来源Agent返回后，取真实agent_id，生成compare参数并原样resume同一Agent。工具自动纳入全部声明必交件和当前SHA；父任务不另挑一份清单。仅明确聊天必答时加--reply-file OUTPUT/final_reply.md：
PY SCRIPT/review_request.py compare --record WORK/review.json --agent-id ID
正确稿保持原样，不提供润色建议。只有有来源依据的实质错误或遗漏才做一次最小修复/补齐，并用同一记录recheck最多一次；漏声明可用--add-required-artifact补入，遗漏的聊天必答可加--reply-file，不能移除旧件或换记录清零。把返回参数交给同一Agent实际读取全部受审文件和关联内容：
PY SCRIPT/review_request.py recheck --record WORK/review.json --agent-id ID
复核结束后从同一记录交付，不手填另一份artifact清单或期望SHA：
PY SCRIPT/review_request.py handoff --record WORK/review.json --agent-id ID --register-stop
只在当前项目已初始化可选门控时保留--register-stop；否则省略，不自行安装Hook。handoff自动派生全部已请求复核的必交件、版本及可选回复；缺件、声明与请求集合不一致或版本变化时失败，不输出半份回执。默认reply_lines是中性文件链接，有已绑定回复时才是该回复全文。底层content_check.py handoff不证明本轮完整集合已闭合，不能在此流程中绕过记录。
工具只绑定已声明集合，不能自动理解用户全部要求，也不能证明Agent实际调用、完整读取或语义正确；新上下文可能共享模型错误。验收同时核对原要求是否全部声明、真实Agent读取覆盖、内容与保存版本，不能仅以来源先后、参数生成或版本一致代替。超限或工具不可用时保留成果并说明未覆盖范围，不删文件或必答凑通过。


## 适用边界

- 独立复核使用同一模型的新上下文，仍可能共同漏判范围推定或附加计数说明；重要结论需要按实际风险人工复核。
- 工具绑定的是显式声明的交付集合与版本，不会自动理解所有自然语言要求，也不认证调用者提供的Agent ID；不能把版本相同或matched当作内容正确。
- 可选Stop门控只触发有界纠正，不保证初始回复在界面上消失，也不保证每次最终措辞都能完全一致或partial提示必定可见。
- 普通闲聊的门控逻辑有程序测试，本轮未另做完整宿主闲聊专项；原生Agent和最终回复逐字约束存在上述已记录偏离，相关严格runtime字段保留false。
- 实际宿主和项目Hook验证范围为macOS与本次Flash模型；其他系统或模型需先做随包自检及实际发现测试，未验证的平台不猜测启用。
- 同名旧版或人工定制技能将保留并报告冲突，不自动覆盖升级。安装提问连同必要原生确认最多5个，不读取个人记忆、不关闭安全设置。
- 分享包只含通用工具、虚构自检数据及公开汇总，不包含真实任务材料、账户信息、个人记忆、私有评测答案或运行日志。

同一模型换检查步骤不等于第二个独立模型。程序通过、文件安装、产品发现、实际读取和任务正确分别核验。本轮不增强在线检索，不保证所有任务零错误，也不折算为统一能力分数。

Word手册仅做OOXML结构、Normal标题无段落边框及33份源码字节往返校验；本机LibreOffice/soffice有意禁用，跳过视觉渲染QA。没有据此声称其他电脑原生Office显示或产品激活已通过。
